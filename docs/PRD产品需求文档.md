## 一、产品概述

### 1.1 产品定位

CRM-sale-Agent 是面向 B2B 实体产品销售场景的智能 Agent 系统。系统通过 LLM 驱动的任务拆解、多工具串并行调度、RAG 事实验真机制，在 15 秒内输出可信、结构化、可直接用于客户沟通的销售方案。

### 1.2 产品目标

| 目标 | 量化指标 | 优先级 |
|------|----------|--------|
| 方案生成提速 | P95 ≤15 秒 | P0 |
| 数据可信保障 | 幻觉检出率 ≥90% | P0 |
| 输出标准化 | JSON 解析成功率 ≥90% | P0 |
| 报价一致性 | 数值偏差率 ≤2% | P1 |
| 成本控制 | Token ≤4000/请求 | P2 |

### 1.3 产品架构概览

```
┌─────────────────────────────────────────────┐
│              用户交互层                      │
│   前端调试页面 / CRM 系统 API 调用           │
├─────────────────────────────────────────────┤
│              API 服务层                      │
│   FastAPI (9个端点) / CORS / 异常处理        │
├─────────────────────────────────────────────┤
│              Agent 编排层                    │
│   任务拆解 → 工具调度 → 方案生成 → 反思验真   │
├──────────────┬──────────────────────────────┤
│   工具层     │         服务层                │
│  4+1个工具   │  缓存/监控/NL2SQL/客户/PDF    │
├──────────────┴──────────────────────────────┤
│              存储层                           │
│   SQLite/MySQL/PG + Chroma向量库 + Redis     │
└─────────────────────────────────────────────┘
```

## 四、功能需求规格

### 4.1 FR-01：销售咨询（核心功能）

**功能描述**：接收客户咨询文本，自主拆解任务、调度工具、生成方案、反思验真，返回标准化 JSON。

**接口规格**：

```
POST /api/chat/sales
请求体: SalesQueryRequest
响应体: SalesResponse
```

**请求模型**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| query | string | 是 | 客户咨询文本（≤2000字符） |
| customer_id | string | 否 | 客户 ID（如 C-001） |
| product_category | string | 否 | 产品类别 |

**响应模型**（SalesResponse）：

| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | success / partial / error |
| inventory | InventoryInfo | 库存信息 |
| pricing | PricingInfo | 价格信息 |
| cases | List[CaseInfo] | 相似案例列表 |
| proposal | ProposalInfo | 销售方案 |
| customer_profile | CustomerProfile | 客户画像 |
| follow_ups | List[FollowUpRecord] | 跟进记录 |
| reflection_report | ReflectionReport | 反思验真报告 |
| task_logs | List[TaskLog] | 任务执行日志 |

**处理流程**：

```
Step1: TaskPlanner.plan(query)
       → LLM 拆解为 4 类标准化任务（temperature=0.3）
       → 降级: _get_default_tasks() 规则匹配

Step2: ToolDispatcher.dispatch(tasks)
       → 按优先级分组（1/2/3）
       → 依赖检查 + 同优先级并行（asyncio.gather）
       → 超时控制（asyncio.wait_for, 30s）

Step3: SalesAgent._build_response()
       → 组装库存/价格/案例/客户数据
       → _generate_proposal() LLM 生成方案（temperature=0.7）
       → 降级: _generate_fallback_proposal() 规则生成

Step4: ReflectionEngine.verify() [可选,默认启用]
       → 边界校验 → 业务规则校验 → 数据源比对
       → 置信度 < 0.8 → status=partial
```

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-01 | 输入"采购50台工业风机" | 返回包含库存+价格+案例+方案的 SalesResponse |
| AC-02 | 输入无效产品名 | 返回 status=error，error message |
| AC-03 | LLM 不可用时 | 降级为规则方案，status=partial |
| AC-04 | 工具超时 | 跳过该任务，继续其他任务 |
| AC-05 | 反思置信度<0.8 | status=partial，附带风险提示 |

### 4.2 FR-02：任务拆解

**功能描述**：LLM 将客户咨询拆解为标准化子任务队列。

**任务类型**：

| 任务类型 | 工具 | 优先级 | 依赖 |
|----------|------|--------|------|
| inventory_query | api_inventory | 1 | 无 |
| price_query | sql_price | 2 | 无 |
| case_retrieval | doc_retrieve | 2 | 无 |
| price_calculation | calculator | 3 | inventory_query, price_query |

**Prompt 设计**：

| Prompt 元素 | 内容 |
|-------------|------|
| 角色锁定 | "你是 B2B 销售任务拆解专家" |
| 任务规则 | 4 类标准化任务定义 |
| 优先级规则 | 1→2→3 分组执行 |
| 依赖规则 | price_calculation 依赖前序任务 |
| 输出格式 | JSON 数组，含 task_type/priority/dependencies/params |
| 温度 | 0.3（低随机性） |

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-06 | 输入"查询工业风机库存" | 拆解为 1 个 inventory_query 任务 |
| AC-07 | 输入综合采购需求 | 拆解为 4 类任务，依赖正确 |
| AC-08 | LLM 返回非 JSON | 降级为默认任务队列 |
| AC-09 | 输入模糊需求 | 匹配最接近的任务类型 |

### 4.3 FR-03：工具调度

**功能描述**：按优先级分组、依赖检查、并行执行工具。

**调度策略**：

```
Priority 1: inventory_query (独立执行)
    ↓
Priority 2: price_query + case_retrieval (并行执行)
    ↓
Priority 3: price_calculation (等待 1+2 完成后执行)
```

**超时控制**：每个工具调用超时 30 秒（`TOOL_TIMEOUT=30`）。

**Context 传递**：前序任务结果通过 `context[task_type]` 注入后续任务参数。

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-10 | 4 个任务全部执行 | 4 条 task_log，状态均为 completed |
| AC-11 | 某工具超时 | 该任务状态 failed，其他任务不受影响 |
| AC-12 | 同优先级任务 | 并行执行，总耗时≈最长单任务耗时 |

**输入**：product_name（产品名称）

**输出**：均价、价格区间、折扣率、近期成交记录

**数据源**：SQLite deal_records 表（参数化查询，防注入）

**缓存策略**：TTL=7200 秒（价格缓存）

**验收标准**：

| AC 编号 | 条件 | 预期结果 |

| AC-18 | SQL 参数化 | 无注入风险 |

### 4.6 FR-06：案例文档检索工具

**功能描述**：向量检索相似成交案例。

**输入**：query（查询文本）、top_k（返回数量，默认 3）

**输出**：相似案例列表，含相似度分数

**技术栈**：LlamaIndex + Chroma + BGE-small-zh-v1.5

**缓存策略**：TTL=86400 秒（案例缓存）

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-19 | 检索相似案例 | 返回 top-k 案例，含相似度分数 |
| AC-20 | 无匹配案例 | 返回空列表 |
| AC-21 | 相似度阈值 | 相似度 <0.6 的结果标记低置信 |

### 4.7 FR-07：价格计算工具

**功能描述**：高精度价格计算。

**计算项**：

| 计算项 | 公式 | 说明 |
|--------|------|------|
| 阶梯折扣 | 按数量区间 | 100+台 8折，50+台 9折等 |
| 总价 | 单价×数量×折扣率 | Decimal 高精度 |
| 毛利 | 总价 - 成本 | 需传入成本参数 |
| 账期成本 | 总价×年化利率×账期/365 | 年化 6% |

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-22 | 计算 50 台 9 折总价 | 结果精确到分 |
| AC-23 | 计算账期成本 | 30 天账期成本正确 |
| AC-24 | Decimal 精度 | 无浮点误差 |

### 4.8 FR-08：反思验真引擎

**功能描述**：对 Agent 输出做分层验真，量化幻觉风险。

**三层校验**：

| 层级 | 校验器 | 校验内容 |
|------|--------|----------|
| L1 | BoundaryValidator | 库存≥0、价格>0、折扣 0-1、数量合理、相似度 0-1 |
| L2 | BusinessRuleValidator | 可用≤总库存、总价=单价×数量×折扣、折扣合理区间 |
| L3 | 数据源比对 | 输出数据与数据库真值比对（5% 容差） |

**输出**：ReflectionReport

| 字段 | 类型 | 说明 |
|------|------|------|
| overall_confidence | float | 综合置信度（0-1） |
| status | string | passed / warning / failed |
| fields | List[ReflectionField] | 各字段校验结果 |
| hallucinations_detected | List[string] | 检出的幻觉列表 |

**配置**：`REFLECTION_ENABLED=true`，`REFLECTION_CONFIDENCE_THRESHOLD=0.8`

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-25 | 数据全部正确 | confidence ≥0.8，status=passed |
| AC-26 | 数据被篡改 | 检出幻觉，confidence <0.8 |
| AC-27 | 关闭反思 | 跳过验真，直接返回 |

### 4.9 FR-09：销售方案生成

**功能描述**：LLM 基于真实数据生成结构化销售方案。

**方案字段**（ProposalInfo）：

| 字段 | 说明 |
|------|------|
| summary | 方案摘要 |
| pricing_strategy | 定价策略 |
| inventory_assurance | 库存保障 |
| payment_recommendation | 付款建议 |
| competitive_advantage | 竞争优势 |
| next_steps | 下一步行动 |
| risk_warnings | 风险提示 |

**降级策略**：LLM 失败时，`_generate_fallback_proposal()` 基于规则生成方案。

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-28 | LLM 正常 | 7 字段完整填充 |
| AC-29 | LLM 失败 | 降级方案，status=partial |
| AC-30 | 方案数据来源 | 仅基于工具返回的真实数据 |

### 4.10 FR-10：NL2SQL 自然语言查询

**功能描述**：自然语言转 SQL 查询业务数据。

**接口规格**：

```
POST /api/db/query
请求体: { "query": "统计上月所有A类客户的采购总额" }
响应体: { "status": "success", "sql": "SELECT...", "data": [...] }
```

**安全机制**：

| 安全措施 | 实现方式 |
|----------|----------|
| 表白名单 | 仅允许 products / customers / deal_records |
| 危险关键词过滤 | DROP / DELETE / UPDATE / INSERT / ALTER 拦截 |
| SELECT 限制 | 仅允许 SELECT 语句 |
| 只读模式 | `PRAGMA query_only = ON` |

**验收标准**：

| AC 编号 | 条件 | 预期结果 |
|---------|------|----------|
| AC-31 | 正常查询 | 返回 SQL + 数据 |
| AC-32 | 包含 DROP | 拦截，返回错误 |
| AC-33 | 查询非白名单表 | 拦截，返回错误 |

### 4.11 FR-11：模型动态切换

## 九、风险与依赖

### 9.1 技术风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| LLM API 不稳定 | 高 | 方案生成失败 | 重试 3 次 + 降级方案 |
| LLM 幻觉 | 高 | 数据不可信 | 反思验真三层校验 |
| 模拟数据与真实差异 | 中 | 评估失真 | 接入真实数据后重新评估 |
| Chroma 向量库性能 | 中 | 检索延迟 | 监控 + 缓存 |
| Ollama 本地模型精度 | 中 | 任务拆解准确率低 | 关键场景使用云端模型 |

### 9.2 依赖项

| 依赖 | 类型 | 说明 |
|------|------|------|
| OpenAI / 智谱 API Key | 外部 | 云端 LLM 调用 |
| Ollama 服务 | 外部 | 本地 LLM 部署 |
| BGE Embedding 模型 | 外部 | 向量化（HuggingFace） |
| Docker 运行时 | 外部 | 容器化部署 |
| Redis（可选） | 外部 | 缓存加速 |
| LangFuse（可选） | 外部 | LLM 追踪 |

### 9.3 已知问题

| 问题 | 描述 | 影响 | 优先级 |
|------|------|------|--------|
| WechatNotifyTool Bug | __init__ 参数名不匹配 | 工具无法注册 | P1 |
| 数据模型重复定义 | customer_service.py 与 output_schema.py 中 CustomerProfile 重复 | 维护困难 | P2 |
| eval() 安全风险 | customer_service.py 使用 eval 解析 tags | 安全隐患 | P1 |
| 限流未接入 | 配置存在但未实现中间件 | 无并发保护 | P1 |
| 监控未埋点 | 指标已定义但未调用 | 无运行时监控 | P1 |
| LLMAdapter 属性重复 | mode/model_name @property 重复定义 | 潜在运行时错误 | P2 |
