## 一、业务分析

### 1.1 业务背景

在 B2B 实体产品销售场景中，销售人员面临以下核心痛点：

| 痛点 | 描述 | 影响程度 |
|------|------|----------|
| **信息分散** | 库存在 ERP、价格在 CRM、案例在文档中，销售需跨系统查询 | 高 |
| **响应滞后** | 客户咨询后需人工汇总数据、计算报价、匹配案例，平均耗时 30-60 分钟 | 高 |
| **报价不一致** | 不同销售给出的价格策略差异大，缺乏历史成交数据支撑 | 中 |
| **经验难复制** | 资深销售的谈判策略和案例匹配经验无法快速传递给新人 | 中 |
| **数据可信度低** | AI 生成方案可能编造数据（幻觉），销售无法直接用于客户沟通 | 高 |

### 1.2 业务目标

**核心目标**：构建一个能自主拆解销售任务、调度多数据源工具、内置事实验真机制的智能 Agent，在 15 秒内输出可信、结构化、可直接用于客户沟通的销售方案。

**分解目标**：

| 目标编号 | 目标描述 | 量化指标 | 优先级 |
|----------|----------|----------|--------|
| G-01 | 缩短销售方案生成时间 | 从 30-60 分钟降至 ≤15 秒（P95） | P0 |
| G-02 | 提升方案数据可信度 | 幻觉检出率 ≥90%，置信度 ≥0.8 | P0 |
| G-03 | 统一报价策略 | 价格计算偏差率 ≤2% | P1 |
| G-04 | 标准化输出格式 | JSON 解析成功率 ≥90%，100% 固定结构 | P1 |
| G-05 | 降低 LLM 调用成本 | 平均 Token 消耗 ≤4000/请求 | P2 |

### 1.3 业务场景定义

#### 场景一：综合采购咨询（核心场景）

```
触发条件：客户提出包含产品、数量、账期、价格对比的综合采购需求
示例输入："采购50台工业风机，想要30天账期，对比往期大客户成交价"
Agent 行为：
  1. 拆解为 4 类子任务（库存查询→价格查询→案例检索→价格计算）
  2. 按优先级串并行调度 4 个工具
  3. 基于真实数据生成销售方案
  4. 反思验真校验所有数据
预期输出：含库存/价格/案例/方案/反思报告的标准化 SalesResponse
```

#### 场景二：单一信息查询

```
触发条件：客户仅需查询库存或价格等单一信息
示例输入："查询工业风机的库存情况"
Agent 行为：
  1. 拆解为 1 类子任务
  2. 执行单个工具
  3. 返回结构化数据
预期输出：含单维度数据的 SalesResponse
```

#### 场景三：NL2SQL 自然语言查询

```
触发条件：业务人员用自然语言查询业务数据
示例输入："统计上月所有A类客户的采购总额"
Agent 行为：
  1. LLM 解析查询意图
  2. 生成 SQL（白名单表过滤 + 危险关键词拦截）
  3. 只读模式执行查询
预期输出：查询结果数据集
```

#### 场景四：模型动态切换

```
触发条件：需要在云端模型（高精度）和本地模型（低成本/隐私）间切换
Agent 行为：运行时无缝切换 LLM 后端，不中断服务
预期输出：切换成功确认 + 新模型信息
```

### 1.4 用户角色分析

| 角色 | 使用场景 | 核心诉求 | 使用频率 |
|------|----------|----------|----------|
| **销售顾问** | 接待客户咨询时快速生成方案 | 速度快、数据准、可直接转发客户 | 高（每日 20-50 次） |
| **销售经理** | 审核报价方案、查看统计 | 方案合规性、一致性、可追溯 | 中（每日 5-10 次） |
| **系统管理员** | 切换模型、监控运行状态 | 运维便捷、监控可视化 | 低（每周 2-3 次） |
| **业务分析师** | NL2SQL 查询业务数据 | 查询灵活、结果准确 | 中（每日 5-10 次） |

### 1.5 业务流程分析

#### 1.5.1 正向流程

```
客户咨询 → 销售提交至 Agent → 任务拆解(LLM) → 工具调度(并行/串行)
    → 数据汇总 → 方案生成(LLM) → 反思验真 → 返回标准化方案 → 销售转发客户
```

#### 1.5.2 异常流程

| 异常类型 | 触发条件 | 处理策略 | 降级方案 |
|----------|----------|----------|----------|
| LLM 调用失败 | API 超时/限流/Key 无效 | 重试 3 次后降级 | 规则匹配生成默认任务 |
| 工具执行超时 | 工具调用 >30 秒 | 超时中断，标记失败 | 跳过该任务，继续其他任务 |
| 反思验真未通过 | 置信度 <0.8 | 标记 status=partial | 返回方案但附带风险提示 |
| 数据库连接失败 | DB 不可达 | 返回 error 状态 | 返回 ErrorResponse |
| JSON 解析失败 | LLM 输出非 JSON | 重试后降级 | 规则生成 fallback 方案 |

### 1.6 业务价值评估

| 价值维度 | 当前状态 | 目标状态 | 预期提升 |
|----------|----------|----------|----------|
| 方案生成效率 | 30-60 分钟/单 | ≤15 秒/单（P95） | 提升 120-240 倍 |
| 报价一致性 | 人工经验依赖，偏差>10% | 数据驱动，偏差≤2% | 提升 5 倍 |
| 数据可信度 | 人工核对，漏检率高 | 自动验真，检出率≥90% | 质变提升 |
| 新人上手周期 | 2-4 周 | 即时可用 | 提升 10 倍 |
| 客户响应满意度 | 需等待，流失率高 | 秒级响应 | 显著提升 |

## 二、AI 量化指标

### 2.1 指标体系总览

AI 量化指标体系覆盖 **5 个核心维度、22 项指标**，权重分配基于业务影响度：

| 维度 | 权重 | 指标数 | 核心关注点 |
|------|------|--------|------------|
| 任务拆解质量 | 20% | 4 项 | LLM 能否正确理解并拆分销售任务 |
| 工具执行准确性 | 25% | 4 项 | 工具返回数据是否与数据库真值一致 |
| 反思验真有效性 | 20% | 5 项 | 幻觉检测能力和误报控制 |
| 方案生成质量 | 15% | 5 项 | LLM 生成的方案是否事实一致、格式合规 |
| 端到端性能 | 20% | 4 项 | 系统响应速度和稳定性 |

### 2.2 维度一：任务拆解质量

| 指标 | 定义 | 计算公式 | 达标线 | 权重 |
|------|------|----------|--------|------|
| 任务类型准确率 | LLM 正确识别任务类型的比例 | `正确识别task数 / 总task数` | ≥90% | 30% |
| 参数提取 F1 | 任务参数提取的精确率与召回率调和值 | `2×P×R/(P+R)` | ≥0.85 | 25% |
| 依赖图匹配率 | 依赖关系与预期一致的比例 | `正确依赖数 / 总依赖数` | ≥95% | 25% |
| 任务数偏差率 | 拆解任务数与预期数的偏差 | `\|实际-预期\|/预期` | ≤10% | 20% |

**测试样本要求**：≥30 条标注样本，覆盖单任务、双任务、三任务、四任务全链路及边界场景。

### 2.3 维度二：工具执行准确性

| 指标 | 定义 | 计算公式 | 达标线 | 权重 |
|------|------|----------|--------|------|
| 字段一致率 | 工具输出与数据库真值的字段级匹配率 | `一致字段数 / 总字段数` | ≥98% | 35% |
| 数值偏差率 | 数值字段的平均偏差比例 | `avg(\|输出-真值\|/真值)` | ≤2% | 25% |
| 工具调用成功率 | 工具正常执行完成的比例 | `成功调用数 / 总调用数` | ≥99% | 25% |
| 缓存命中率 | 工具从缓存获取数据的比例 | `缓存命中数 / 总查询数` | ≥60% | 15% |

**分工具评估要求**：4 个注册工具（calculator / api_inventory / sql_price / doc_retrieve）需独立评估。

### 2.4 维度三：反思验真有效性

| 指标 | 定义 | 计算公式 | 达标线 | 权重 |
|------|------|----------|--------|------|
| 真阳性率 (TPR/召回率) | 正确检出幻觉/错误数据的比例 | `检出的错误数 / 实际错误总数` | ≥85% | 30% |
| 假阳性率 (FPR) | 误报正确数据为错误的比例 | `误报数 / 实际正确数据总数` | ≤5% | 20% |
| 置信度校准误差 | 置信度分数与实际准确率的偏差 | `avg(\|置信度-实际准确率\|)` | ≤0.1 | 20% |
| 边界校验覆盖率 | 数值字段被边界校验覆盖的比例 | `已校验字段数 / 总数值字段数` | 100% | 15% |
| 业务规则违规检出率 | 业务规则错误被检出的比例 | `检出规则错误数 / 总规则错误数` | ≥95% | 15% |

**测试方法**：构造包含正确数据和故意篡改数据的双盲测试集，计算 ROC 曲线和 AUC 值。

### 2.5 维度四：方案生成质量

| 指标 | 定义 | 计算公式 | 达标线 | 权重 |
|------|------|----------|--------|------|
| 事实一致性 | 方案数据是否仅基于提供的数据 | `事实一致字段数 / 方案总字段数` | ≥95% | 25% |
| JSON 解析成功率 | LLM 输出被成功解析的比例 | `解析成功次数 / 总调用次数` | ≥90% | 25% |
| 降级触发率 | 降级方案被触发的比例 | `降级触发次数 / 总请求次数` | ≤10% | 20% |
| 方案结构化程度 | 方案各字段填充完整度 | `非空字段数 / 方案总字段数` | ≥90% | 15% |
| 幻觉检测率 | 编造信息被检出的比例 | `检出幻觉数 / 实际幻觉总数` | ≥90% | 15% |

### 2.6 维度五：端到端性能

| 指标 | 定义 | 计算公式 | 达标线 | 权重 |
|------|------|----------|--------|------|
| P50 响应延迟 | 50% 请求的响应时间 | `sort(响应时间)[len/2]` | ≤5s | 25% |
| P95 响应延迟 | 95% 请求的响应时间 | `sort(响应时间)[len*0.95]` | ≤15s | 30% |
| 成功率 | 返回 success 状态的比例 | `success请求数 / 总请求数` | ≥95% | 25% |
| Token 消耗/请求 | 平均每次请求的 Token 用量 | `总Token消耗 / 请求数` | ≤4000 | 20% |

**各阶段耗时分布目标**：

| 阶段 | 耗时占比目标 | 说明 |
|------|-------------|------|
| 任务拆解 | ≤30% | LLM 调用，温度 0.3 |
| 工具调度 | ≤40% | 含并行执行和超时控制 |
| 方案构建 | ≤20% | LLM 调用，温度 0.7 |
| 反思验真 | ≤10% | 规则校验+数据源比对 |

### 2.7 综合评分模型

```
综合评分 = 任务拆解×20% + 工具准确性×25% + 反思有效性×20% + 方案质量×15% + 端到端性能×20%
```

| 评分等级 | 分数区间 | 含义 |
|----------|----------|------|
| A（优秀） | ≥90 | 可投入生产 |
| B（良好） | 80-89 | 可投入试运行 |
| C（合格） | 70-79 | 需优化后上线 |
| D（不合格） | <70 | 不可上线 |

基于量化评估方案中的示例数据，系统目标基准如下：

| 维度 | 关键指标 | 目标值 | 参考达标线 |

#### 3.3.2 向量数据可行性

#### 3.3.3 LLM 数据可行性

| 分析项 | 现状 | 可行性 | 风险与对策 |
|--------|------|--------|------------|
| OpenAI/智谱 API | 已适配 | ✅ 可行 | 需 API Key，有调用成本 |

### 3.4 数据风险与缓解措施

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 模拟数据与真实数据差异大 | 高 | 工具准确性评估失真 | 接入真实数据后重新评估 |
| 案例文档量不足 | 中 | RAG 检索召回率低 | 扩充至 50+ 篇，覆盖主要行业 |
| 无实时数据同步 | 中 | 库存/价格数据过时 | 开发 ERP/CRM 数据同步接口 |
| 向量索引无增量更新 | 中 | 新案例无法即时检索 | 实现 Chroma 增量索引机制 |
| LLM 幻觉风险 | 高 | 方案数据不可信 | 反思验真引擎三层校验 |

## 四、能力边界

### 4.1 系统能力边界定义

能力边界明确系统**能做什么**和**不能做什么**，防止超出设计范围的误用。

#### 4.1.1 核心能力（系统支持）

| 能力编号 | 能力名称 | 能力描述 | 支持程度 |
|----------|----------|----------|----------|
| C-01 | 销售任务自主拆解 | LLM 将客户咨询拆解为标准化子任务队列 | ✅ 完全支持 |
| C-02 | 多工具串并行调度 | 按优先级分组、依赖检查、并行执行 | ✅ 完全支持 |
| C-03 | 库存查询 | 查询产品库存量、可用量、预留量 | ✅ 完全支持 |
| C-04 | 历史价格查询 | 查询历史成交均价、区间、折扣率 | ✅ 完全支持 |
| C-05 | 案例文档检索 | 向量检索相似成交案例 | ✅ 完全支持 |
| C-06 | 价格计算 | 阶梯折扣、总价、毛利、账期成本计算 | ✅ 完全支持 |
| C-07 | 反思验真 | 数值边界+业务规则+数据源比对三层校验 | ✅ 完全支持 |

### 4.2 输入约束边界

| 幻觉数据 | 不得编造数据 | 反思验真标记 partial |
