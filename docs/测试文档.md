## 二、CI/CD 持续集成方案

### 2.1 当前状态

项目当前**无任何 CI/CD 配置**，无 GitHub Actions、GitLab CI、Jenkinsfile。所有构建、测试、部署均需手动执行。

### 2.2 CI/CD 流水线设计

```
代码提交 (Push/PR)
    ↓
┌── Stage 1: 代码质量检查 ──┐
│  ├── 代码风格检查 (flake8/black)
│  ├── 类型检查 (mypy)
│  └── 安全扫描 (bandit)
├── Stage 2: 单元测试 ────────┤
│  ├── pytest tests/ --cov
│  └── 覆盖率报告 ≥70%
├── Stage 3: 接口测试 ────────┤
│  ├── 启动测试服务
│  └── pytest tests/test_api.py
├── Stage 4: AI 评估测试 ─────┤
│  └── python tests/eval/run_evaluation.py
├── Stage 5: 构建镜像 ────────┤
│  ├── docker build
│  └── 安全扫描镜像
├── Stage 6: 部署 ────────────┤
│  ├── 测试环境自动部署
│  └── 生产环境手动审批
└── Stage 7: 通知 ────────────┘
   ├── 成功: 通知团队
   └── 失败: 告警+阻塞合并
```

### 2.3 GitHub Actions 配置方案

```yaml
# .github/workflows/ci.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  # Stage 1: 代码质量
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.10'
      - run: pip install flake8 black mypy bandit
      - run: flake8 . --count --max-line-length=120 --statistics
      - run: black --check .
      - run: bandit -r . -f json -o bandit-report.json

  # Stage 2: 单元测试
  unit-test:
    runs-on: ubuntu-latest
    needs: lint
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.10'
      - run: pip install -r requirements.txt
      - run: pip install pytest pytest-asyncio pytest-cov
      - run: pytest tests/ --cov=. --cov-report=xml --cov-report=term-missing
      - uses: codecov/codecov-action@v3

  # Stage 3: 接口测试
  api-test:
    runs-on: ubuntu-latest
    needs: unit-test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.10'
      - run: pip install -r requirements.txt
      - run: python main.py &
      - run: sleep 5
      - run: pytest tests/test_api.py -v

  # Stage 4: 构建
  build:
    runs-on: ubuntu-latest
    needs: api-test
    steps:
      - uses: actions/checkout@v4
      - uses: docker/build-push-action@v5
        with:
          context: .
          push: false
          tags: crm-sale-agent:${{ github.sha }}
```

### 5.7 asyncio 并发测试脚本

```python
# tests/load_test/test_concurrent.py
import asyncio
import aiohttp
import time

async def send_request(session, query):
    """发送单个请求"""
    async with session.post("/api/chat/sales", json={
        "query": query
    }) as response:
        return await response.json()

async def concurrent_test(num_concurrent=50):
    """并发测试"""
    queries = [
        "采购50台工业风机",
        "查询离心泵价格",
        "工业阀门库存情况",
        "电力变压器成交案例",
    ]

    async with aiohttp.ClientSession() as session:
        tasks = []
        start_time = time.time()

        for i in range(num_concurrent):
            query = queries[i % len(queries)]
            tasks.append(send_request(session, query))

        results = await asyncio.gather(*tasks, return_exceptions=True)
        total_time = time.time() - start_time

        # 统计结果
        success = sum(1 for r in results if not isinstance(r, Exception))
        errors = sum(1 for r in results if isinstance(r, Exception))

        print(f"并发数: {num_concurrent}")
        print(f"总耗时: {total_time:.2f}s")
        print(f"QPS: {num_concurrent/total_time:.2f}")
        print(f"成功: {success}, 失败: {errors}")
        print(f"错误率: {errors/num_concurrent*100:.1f}%")

# 运行: python -m asyncio tests/load_test/test_concurrent.py
```

### 7.2 幻觉评测

#### 7.2.1 幻觉定义

| 幻觉类型 | 定义 | 示例 |
|----------|------|------|
| 数据编造 | 生成不存在的数据 | 编造库存数量、价格 |
| 数值篡改 | 修改真实数值 | 库存 200→250 |
| 案例虚构 | 编造不存在案例 | 虚构客户成交记录 |
| 关系捏造 | 错误关联数据 | 将 A 客户案例关联到 B |

#### 7.2.2 幻觉检测机制

```
三层校验:
  L1: BoundaryValidator
      → 检测数值越界（库存<0, 价格<0, 折扣>1）
      → 检测不合理数值（库存 999999）

  L2: BusinessRuleValidator
      → 检测逻辑矛盾（可用>总库存）
      → 检测计算错误（总价≠单价×数量×折扣）

  L3: 数据源比对
      → 输出数据 vs 数据库真值
      → 容差 5%（价格类）
      → 精确匹配（库存类）
```

#### 7.2.3 幻觉评测方法

| 方法 | 说明 | 指标 |
|------|------|------|
| 双盲测试 | 构造正确+篡改数据各 50% | TPR/FPR |
| 数据源比对 | 输出 vs DB 真值 | 字段一致率 |
| 人工审核 | 人工标注幻觉 | 人工检出率 |
| 自动检测 | ReflectionEngine | 自动检出率 |

#### 7.2.4 幻觉评测结果（目标）

| 指标 | 定义 | 达标线 | 目标值 |
|------|------|--------|--------|
| 幻觉检出率 (TPR) | 检出的幻觉/实际幻觉 | ≥90% | 92% |
| 误报率 (FPR) | 误报/实际正确 | ≤5% | 3.2% |
| 幻觉发生率 | 生成方案中的幻觉比例 | ≤10% | 7.5% |
| 数据准确率 | 输出数据与真值一致率 | ≥95% | 96.2% |

### C. 评估指标计算公式

| 指标 | 公式 |
|------|------|
| 精确率 (Precision) | `TP / (TP + FP)` |
| 召回率 (Recall/TPR) | `TP / (TP + FN)` |
| F1 Score | `2 × P × R / (P + R)` |
| 假阳性率 (FPR) | `FP / (FP + TN)` |
| 准确率 (Accuracy) | `(TP + TN) / (TP + TN + FP + FN)` |
| AUC | ROC 曲线下面积 |
| MRR | `avg(1 / rank_of_correct)` |

其中：TP=真阳性，FP=假阳性，FN=假阴性，TN=真阴性
