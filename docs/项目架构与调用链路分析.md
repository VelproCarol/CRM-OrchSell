## 二、模块调用链路总览

### 2.1 服务启动初始化链路

```
main.py
  ├── setup_logging()                # 配置日志系统（loguru）
  │
  ├── initialize_system()            # 系统初始化
  │   ├── storage/init_sql.py        # 初始化 SQLite 数据库
  │   │   ├── 创建 products 表（产品信息）
  │   │   ├── 创建 deal_records 表（历史成交订单）
  │   │   ├── 创建 customers 表（客户档案）
  │   │   └── 插入模拟数据（8个产品）
  │   │
  │   └── storage/init_vector_db.py  # 初始化 Chroma 向量库
  │       ├── 加载本地 BGE Embedding 模型
  │       ├── 读取 docs/ 目录文档（.md/.txt/.json）
 │       └── 生成向量索引（5个模拟案例）
  │
  ├── create_app()                   # 创建 FastAPI 应用
  │   ├── api/chat_route.py
  │   │   ├── 注册 APIRouter（路由前缀 /api）
  │   │   ├── 配置 CORS 中间件
  │   │   └── 注册全局异常处理器
  │   └── 返回 FastAPI 实例
  │
  └── uvicorn.run()                  # 启动 ASGI 服务器
```

### 2.2 API 请求处理链路

```
HTTP Request
  └── api/chat_route.py
      ├── POST /api/chat/sales      # 销售咨询接口（主入口）
      │   ├── get_agent()           # 获取/初始化 SalesAgent 单例
      │   │   └── SalesAgent.__init__()
      │   │       ├── get_llm()     # 获取 LLMAdapter 单例
      │   │       ├── TaskPlanner() # 任务拆解器
      │   │       ├── ToolDispatcher() # 工具调度器
      │   │       └── ReflectionEngine() # 反思验真引擎
      │   │
      │   └── agent.process()       # Agent 主处理流程
      │       ├── Step 1: task_planner.plan()   # 任务拆解
      │       ├── Step 2: tool_dispatcher.dispatch() # 工具调度
      │       ├── Step 3: _build_response()      # 构建响应
      │       ├── Step 4: reflection_engine.verify() # 反思验真
      │       └── Step 5: 组装 TaskLog 返回
      │
      ├── GET /api/health           # 健康检查接口
      ├── GET /api/stats            # 统计信息接口
      ├── GET /api/tools            # 工具列表接口
      └── POST /api/init            # 数据库初始化接口
```

### 2.3 Agent 内部处理链路（核心）

```
SalesAgent.process(query, customer_id, product_category)
  │
  ├── Step 1: 任务拆解
  │   └── TaskPlanner.plan()
  │       └── llm_adapter.chat()   # 调用大模型拆解任务
  │           ├── 构造 SYSTEM_PROMPT（角色+规则+格式约束）
  │           ├── 发送用户咨询文本
  │           └── 解析返回 JSON → List[TaskPlan]
  │               ├── task_type: inventory_query/price_query/case_retrieval/price_calculation
  │               ├── tool_name: api_inventory/sql_price/doc_retrieve/calculator
  │               ├── parameters: {product_name, quantity...}
  │               ├── priority: 1/2/3
  │               └── dependencies: []/["inventory_query", "price_query"]
  │
  ├── Step 2: 工具调度执行
  │   └── ToolDispatcher.dispatch(tasks)
  │       ├── _group_by_priority()  # 按优先级分组
  │       ├── 循环按优先级执行
  │       │   ├── _check_dependencies() # 检查依赖是否满足
  │       │   └── _execute_parallel()   # 并行执行同优先级任务
  │       │       └── _execute_single() # 执行单个任务
  │       │           ├── 获取工具实例 self._tools[tool_name]
  │       │           ├── 合并参数 {**task.parameters, **context}
  │       │           ├── asyncio.wait_for(tool.execute(**params), timeout=30s)
  │       │           │   ├── tools/api_inventory_tool.py  # 库存查询
  │       │           │   ├── tools/sql_price_tool.py      # 价格查询
  │       │           │   ├── tools/doc_retrieve_tool.py   # 案例检索
  │       │           │   └── tools/calculator_tool.py     # 价格计算
  │       │           └── 记录 TaskLog（成功/失败/超时）
  │       └── 更新 context（供下游任务使用）
  │
  ├── Step 3: 构建响应数据
  │   └── SalesAgent._build_response(context)
  │       ├── 解析 inventory_query 结果 → InventoryInfo
  │       ├── 解析 price_query 结果 → PricingInfo
  │       ├── 解析 case_retrieval 结果 → List[CaseInfo]
  │       └── _generate_proposal()  # 调用大模型生成销售方案
  │           ├── 构造 PROPOSAL_PROMPT（库存+价格+案例+需求）
 │           ├── llm_adapter.chat()
  │           └── _parse_proposal() # 解析 JSON 为 ProposalInfo
  │
  ├── Step 4: 反思验真（可选，默认启用）
  │   └── ReflectionEngine.verify(response, context)
  │       ├── _verify_inventory()   # 比对库存数据真实性
  │       ├── _verify_pricing()     # 比对价格数据真实性
  │       ├── _verify_cases()       # 比对案例数据真实性
  │       └── 计算 overall_confidence（已验证字段 / 总字段）
  │           ├── confidence >= 0.8 → status = "success"
  │           └── confidence < 0.8  → status = "partial" + 警告
  │
  └── Step 5: 组装最终响应
      └── SalesResponse(
          status, message,
          inventory, pricing, cases, proposal,
          reflection_report, task_logs,
          customer_id, query, product_category, timestamp
      )
```

## 三、核心模块职责与交互关系

### 3.1 单例模式实例

| 单例 | 所在模块 | 创建时机 | 用途 |
|------|---------|---------|------|
| `settings` | `config/settings.py` | 模块导入时 | 全局配置读取（.env） |
| `_llm_adapter` | `core/llm_adapter.py` | 首次 `get_llm()` 调用 | 大模型调用封装 |
| `_agent` | `api/chat_route.py` | 首次请求时 | SalesAgent 实例复用 |

### 3.2 策略模式：LLM 适配器

```
BaseLLMAdapter (抽象基类)
  ├── OpenAIAdapter                # 云端模式（智谱/ OpenAI）
  │   └── llama_index.llms.openai.OpenAI
  └── QwenAdapter                  # 本地私有化模式（Ollama）
      └── llama_index.llms.ollama.Ollama

LLMAdapter (统一入口)
  └── 根据 settings.LLM_MODE 自动选择适配器
```

### 3.3 模板方法模式：工具基类

```
BaseTool (抽象基类)
  ├── execute(**kwargs)            # 子类必须实现
  ├── validate_params(**kwargs)    # 子类可覆盖
  ├── _get_parameters_schema()     # 子类必须实现
  ├── _handle_error()              # 通用错误处理
  └── _success_response()          # 通用成功响应

具体工具实现:
  ├── CalculatorTool               # 高精度数值计算
  ├── ApiInventoryTool             # 模拟 CRM 库存查询
  ├── SqlPriceTool                 # SQLite 历史价格查询
  └── DocRetrieveTool              # Chroma 向量案例检索
```

## 六、异常处理路径

```
工具执行异常:
  ToolDispatcher._execute_single()
    ├── asyncio.TimeoutError → TaskLog(status="failed", error="超时")
    └── Exception            → TaskLog(status="failed", error=str(e))

Agent 处理异常:
  SalesAgent.process()
    └── Exception → SalesResponse(status="error", message=str(e))

全局异常:
  api/chat_route.py:global_exception_handler()
    └── 返回 JSONResponse(status_code=500, detail=str(exc))
```

## 八、配置驱动的模块选择

| 配置项 | 取值 | 影响的模块 |
|--------|------|-----------|
| `LLM_MODE=openai` | openai | `core/llm_adapter.py` → OpenAIAdapter |
| `LLM_MODE=qwen` | qwen | `core/llm_adapter.py` → QwenAdapter |
| `USE_LOCAL_EMBEDDING=True` | True | `storage/init_vector_db.py` → 本地 BGE 模型 |
| `USE_LOCAL_EMBEDDING=False` | False | `storage/init_vector_db.py` → HuggingFace 在线模型 |
| `USE_MOCK_DATA=True` | True | `tools/api_inventory_tool.py` → 模拟数据 |
| `REFLECTION_ENABLED=True` | True | `core/sales_agent.py` → 启用反思验真 |
| `REDIS_ENABLED=True` | True | `services/cache_manager.py` → Redis 缓存 |
| `REDIS_ENABLED=False` | False | `services/cache_manager.py` → 内存缓存 |
| `LANGFUSE_ENABLED=True` | True | `services/langfuse/langfuse_monitor.py` → LLM 追踪 |
| `LANGFUSE_ENABLED=False` | False | `services/langfuse/langfuse_monitor.py` → 禁用追踪 |

## 九、新增服务模块详解

### 9.1 客户管理服务（CustomerService）

**模块位置**: `services/customer_service.py`

**核心功能**:
- 客户画像管理（CustomerProfile）
- 跟进记录管理（FollowUpRecord）
- 客户分级（A/B/C/D）
- 信用评级管理
- 采购历史统计

**调用链路**:
```
SalesAgent.process()
  └── get_customer_service()
      └── CustomerService()
          ├── get_customer_profile(customer_id)  # 获取客户画像
          ├── update_customer_profile()          # 更新客户信息
          ├── add_follow_up_record()             # 添加跟进记录
          └── get_purchase_history()             # 获取采购历史
```

**数据模型**:
```python
CustomerProfile:
  - customer_id: str              # 客户ID
  - customer_name: str            # 客户名称
  - industry: str                 # 所属行业
  - company_size: str             # 公司规模
  - customer_level: str           # 客户等级(A/B/C/D)
  - total_purchase_amount: float  # 累计采购金额
  - purchase_count: int           # 采购次数
  - credit_rating: str            # 信用评级
  - tags: List[str]               # 标签列表
```

### 9.2 缓存管理服务（CacheManager）

**模块位置**: `services/cache_manager.py`

**核心功能**:
- Redis 缓存管理（可选）
- 内存缓存后备方案
- 缓存键管理
- TTL 过期控制
- 缓存命中率统计

**调用链路**:
```
ToolDispatcher._execute_single()
  └── cache_manager.get(cache_key)
      ├── Redis 可用 → redis.get(key)
      └── Redis 不可用 → memory_cache.get(key)
  └── cache_manager.set(cache_key, data, ttl)
      ├── Redis 可用 → redis.setex(key, ttl, data)
      └── Redis 不可用 → memory_cache[key] = {data, expire_at}
```

**缓存策略**:
| 数据类型 | 缓存键格式 | TTL | 说明 |
|---------|-----------|-----|------|
| 库存数据 | `inventory:{product_name}` | 3600s (1小时) | 实时性要求高 |
| 价格数据 | `pricing:{product_name}:{quantity}` | 7200s (2小时) | 变动频率中等 |
| 案例数据 | `cases:{query_hash}` | 86400s (24小时) | 变动频率低 |

## 十、性能优化与缓存策略

### 10.1 缓存架构

```
┌─────────────────────────────────────────┐
│           ToolDispatcher                 │
│  ┌─────────────────────────────────────┐ │
│  │  检查缓存: cache_manager.get(key)   │ │
│  │    ├── 缓存命中 → 直接返回           │ │
│  │    └── 缓存未命中 → 执行工具         │ │
│  │         └── cache_manager.set()     │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
       ↓
┌─────────────────────────────────────────┐
│          CacheManager                    │
│  ┌──────────┐        ┌──────────────┐   │
│  │  Redis   │  或    │  Memory Cache│   │
│  │ (可选)   │        │  (后备方案)   │   │
│  └──────────┘        └──────────────┘   │
└─────────────────────────────────────────┘
```

### 10.2 缓存键设计

```python
# 库存缓存键
cache_key = f"inventory:{product_name}"

# 价格缓存键（包含数量参数）
cache_key = f"pricing:{product_name}:{quantity}"

# 案例缓存键（基于查询内容哈希）
cache_key = f"cases:{hashlib.md5(query.encode()).hexdigest()}"

# 客户画像缓存键
cache_key = f"customer:{customer_id}"
```

### 10.3 缓存失效策略

| 场景 | 失效策略 | 说明 |
|------|---------|------|
| 库存变动 | 手动清除 | 库存更新后清除相关缓存 |
| 价格调整 | 手动清除 | 价格调整后清除相关缓存 |
| 新增案例 | 自动失效 | 24小时后自动失效 |
| 客户信息更新 | 手动清除 | 客户信息修改后清除 |

## 十二、扩展开发指南

### 12.1 新增工具开发流程

1. **创建工具类**（继承 BaseTool）
2. **实现 execute 方法**
3. **注册到 ToolDispatcher**
4. **编写单元测试**
5. **更新文档**

**示例代码**:
```python
# tools/my_custom_tool.py
from tools.base_tool import BaseTool, ToolResult

class MyCustomTool(BaseTool):
    def __init__(self):
        super().__init__(
            tool_name="my_custom_tool",
            tool_description="自定义工具描述"
        )

    async def execute(self, **kwargs) -> ToolResult:
        # 参数验证
        self.validate_params(**kwargs)

        # 执行逻辑
        result = await self._process(**kwargs)

        # 返回结果
        return ToolResult(
            status="success",
            data=result,
            message="执行成功"
        )
```

3. **集成到 Agent 流程**

5. **更新文档**

**示例代码**:

# services/my_service.py
from loguru import logger

class MyService:
